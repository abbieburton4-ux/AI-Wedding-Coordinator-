### C2 · Region dropdown unchanged after seed county relabel — pre-filter returns 0 for Dublin/Kerry
**Files:** `streamlit_mock/app.py:211`, `streamlit_mock/agents.py:369-377`
**Severity:** Silent regression — venue_matcher pre-filter now returns 0 in-region matches for the most common selections.

Commit `bc7e4a34` correctly relabeled three venues to their actual counties:
- Hotel Doolin: Kerry → **Clare**
- Castle Leslie: Leinster → **Monaghan**
- Millhouse Slane: Dublin → **Meath**

But the region selector at `app.py:211` still hardcodes `["Sligo", "Dublin", "Galway", "Kerry", "Leinster"]`. After-seed venue distribution:

| Region option | Venues that match exactly |
|---|---|
| Sligo | 2 (Markree, Sligo Community Hall) |
| Dublin | **0** (Millhouse Slane moved to Meath) |
| Galway | 1 (Aniar) |
| Kerry | **0** (Hotel Doolin moved to Clare) |
| Leinster | 1 (Tullamore GAA) |

The venue_matcher pre-filter at `agents.py:369` uses strict equality (`v["region"].lower() == preferred_region.lower()`). When `venues_in_region` is shorter than 3, the fallback at line 374 silently fills the candidate list with venues from *other* regions — and the LLM never knows the preferred region had 0 matches. The judge-facing "AI Match Rationale" reads as if the matcher had real choices to rank, when in fact it's ranking the first 3 venues from an arbitrary fallback set.

**Fix (10 min):** Expand the dropdown to all 7 seeded county labels + the "Leinster" macro:
```python
region = st.selectbox(
    "Preferred Region in Ireland",
    ["Sligo", "Galway", "Kerry", "Clare", "Monaghan", "Meath", "Offaly", "Leinster"]
)
```
And in the matcher pre-filter, add `region_match_count` to the `input_payload` so the LLM can flag fallback transparently in its rationale:
```python
input_payload["wedding_profile"]["venues_matching_region_count"] = len(venues_in_region)
```

### H2 · Whitelist comparison is case-sensitive — false-positive guardrail blocks on "Venue"
**File:** `streamlit_mock/agents.py:211-212`

The whitelist check:
```python
invalid_categories = sorted({
    line.get("category") for line in result_dict.get("budget_lines", [])
    if line.get("category") not in ALLOWED_BUDGET_CATEGORIES
})
```

Strict set membership. If Gemini returns `"Venue"` (capitalized) instead of `"venue"` — which it absolutely can do despite the Field description — the run gets blocked as `category_whitelist`. From the judge's perspective this looks like the guardrail working; from a planner's perspective the workflow stops with an unhelpful error.

**Fix (5 min):** Normalize before comparison and before insert:
```python
def _normalize_category(raw):
    return (raw or "").strip().lower()

invalid_categories = sorted({
    _normalize_category(line.get("category")) for line in result_dict.get("budget_lines", [])
    if _normalize_category(line.get("category")) not in ALLOWED_BUDGET_CATEGORIES
})
```
And apply `_normalize_category(line["category"])` when building `budget_lines_to_insert` at `agents.py:248`, otherwise downstream `WHERE category = ?` queries miss mixed-case rows.
